# Gen Governance Core Skill

This skill regenerates three governance runtime artifacts at the repository root plus an audit sidecar:

| Level | File | Format | Consumed by | Purpose |
|------|------|--------|-------------|---------|
| L2 (canonical) | `.governance/CORE.md` | imperative prose, grouped | `SessionStart`, `PostCompact` | full reference |
| L1 (mini) | `.governance/MINI.md` | imperative prose, per-turn-relevant rules only | `UserPromptSubmit` | attention amplifier, gated every N turns |
| L3 (subagent) | `.governance/SUBAGENT.md` | imperative prose, subagent-tuned subset | `SubagentStart` | subagent-tuned subset |
| audit sidecar | `.governance/meta.yaml` | plain YAML | nothing at runtime — humans, diffs, drift detection | source provenance + SHA-256 fingerprints |

All three `.md` payloads are prose. They are NOT YAML. They contain no rule
IDs, no source anchors, no priority/trigger/category fields. Density of
behavioral content wins over machine-parseability — the agent reads them,
not a parser. Rule traceability lives in `.governance/meta.yaml` plus the
source documents.

The LLM produces all three `.md` files directly during a single regeneration
pass (no deterministic post-filter). This keeps L1 and L3 truly tuned to
their consumers instead of mechanically derived.

Humans do not read these files. Humans read the source documents listed below.

## When To Use
- A `.governance/.dirty` marker exists at the repository root.
- Any governance source document was edited since the last regeneration.
- A human explicitly invokes `/gen-governance-core`.

Only humans invoke this skill. Subagents and automated hooks must not invoke it.
Hooks may only mark the file as dirty.

## Governance Source Documents
Read every source that exists. If a source is missing, skip it without failing.

1. `AGENTS.md` (mandatory)
2. `INTEGRITY-RULES.md` (mandatory)
3. `CLAUDE.md` (mandatory; project-level only — do NOT read `~/.claude/CLAUDE.md`)
4. `docs/PROJECT_SPECS.md` (mandatory if present)
5. `docs/EPICOS.md` (optional; tolerate absence)
6. `docs/decisions.md` (optional; tolerate absence)
7. `docs/language-policy.md` (mandatory)
8. `.governance/.dirty` (optional; if present, contains the list of files that triggered the regeneration — use it to focus extraction effort, but always read all sources for full coverage)

## Workflow
1. Read `references/template.yaml` and `references/extraction-prompt.md`.
2. Read every available source listed above.
3. Compute SHA-256 of each source for the `meta.yaml` `sources` block.
4. Apply the extraction protocol in `references/extraction-prompt.md` to
   distill the sources into imperative prose, organized by visual priority
   (INTEGRITY → BLOCKING → HIGH → DECISION CRITERIA).
5. Write `.governance/CORE.md` (L2, full reference, every section).
6. Write `.governance/MINI.md` (L1 recency nudge — keep only rules that change
   behavior mid-turn: INTEGRITY excluding boundary-only rules (worktree isolation
   stays in CORE/SUBAGENT, not the mini) + BLOCKING — always (relabeled AUTONOMY);
   OMIT `BLOCKING — before declaring done` and all HIGH sections — those are
   boundary rules already injected at SessionStart/PostCompact via CORE; target
   ≤ 1500 bytes).
7. Write `.governance/SUBAGENT.md` (L3, CORE structure minus `before task start`
   and `on compaction` sections).
8. Write `.governance/meta.yaml` (audit sidecar) with `generated_at`, `generator`,
   `sources[]` (each with `path` and `sha256`), and optional `sources_missing[]`.
   Hooks NEVER inject this file; it exists for drift detection in git diffs and audit.
9. Run `bash skills/gen-governance-core/scripts/validate-size.sh` to verify each hook
   output (with its wrapper) is under 10,000 characters (Claude Code cap). If any
   level fails, the regeneration has violated its size invariant — stop and report.
10. Delete `.governance/.dirty` if present.
11. Report a summary listing: files read, total bullet counts per section,
    any sources that were missing, byte sizes of the three artifacts, and a
    PASS/FAIL on the 10K cap.

## Output Contract (payload files)
Each generated `.md` MUST:

- Start with the warning line: `<!-- AUTO-GENERATED by gen-governance-core. Run /gen-governance-core to refresh. Metadata in .governance/meta.yaml. -->`
- Contain only the prose section headers defined in
  `references/template.yaml` (no YAML code fence, no metadata block).
- Use the exact section labels and order specified in the extraction
  protocol (`INTEGRITY (NEVER violate):` → `BLOCKING — <trigger>:` →
  `HIGH — <trigger>:` → `DECISION CRITERIA (CDT — …):`).
- Be written entirely in English.
- Contain no markdown tables, no commentary, no human-targeted explanation.
- Stay under the 10,000-character cap once wrapped by `inject-level.sh`.

Budgets (bytes, file body alone, before hook wrapper):
- `CORE.md`: target ≤ 5000.
- `MINI.md`: target ≤ 1500.
- `SUBAGENT.md`: target ≤ 5000.

The companion `.governance/meta.yaml` MUST:

- Live in the `.governance/` directory next to `CORE.md`.
- Be plain YAML (no markdown wrapper).
- Contain: `generated_at` (ISO 8601 UTC), `generator`, `sources[]` (with
  `path` and `sha256` per entry), and optional `sources_missing[]`.
- Be versioned in git so source drift is visible in diffs.
- Be written entirely in English.
- Contain no commentary, no human-targeted explanation, no markdown tables.

## Extraction Rules
- One imperative sentence per bullet. Period at the end.
- No rule IDs, no source anchors, no priority/trigger fields, no
  rationale blocks. Embed a short qualifier inside the sentence when the
  WHY is needed to judge an edge case.
- Group by visual priority and trigger using the exact section labels in
  the extraction protocol. Omit a section entirely when it has no bullets.
- Drop content that is purely descriptive, narrative, or derivable from a
  Golden Rule already captured in INTEGRITY.
- If two sources express the same rule, emit a single bullet that
  faithfully covers both.
- Preserve the project's existing CDT taxonomy (`CDC-xxx`) by name when
  present in `docs/PROJECT_SPECS.md` Section 10.
- Behavioral parity is mandatory: every rule from the previous
  `.governance/CORE.md` must appear as one bullet in the new payload.

## Mandatory Rules
- Output file paths are fixed under the `.governance/` directory.
- Output language: English only.
- Never write to source documents during regeneration.
- Never invoke other skills.
- Never commit. The human decides when to commit `.governance/CORE.md`.
- Tolerate any missing optional source without failing the regeneration.

## Required Output
- `.governance/CORE.md` (L2 payload) rewritten in prose.
- `.governance/MINI.md` (L1 payload) rewritten in prose.
- `.governance/SUBAGENT.md` (L3 payload) rewritten in prose.
- `.governance/meta.yaml` (sidecar) rewritten in YAML.
- `.governance/.dirty` removed if it existed.
- Brief execution report listing sources read, sources missing, bullet
  counts per section, byte sizes of each artifact, and PASS/FAIL on the
  10K-char cap.

## Runtime Hooks (context-exhaustion guard + handoff)
Besides the governance injection hooks, this skill ships a per-turn context guard
wired through `hooks/user-prompt.sh`:

- `hooks/context-guard.sh` — runs every turn. Reads the current context-window
  usage from `scripts/context-meter.sh` and, once usage crosses thresholds,
  injects an escalating `<context-guard>` system-reminder:
  - `>= CLAUDE_GOV_CTX_WARN` (default 75%) — warning: wind down, no large new work.
  - `>= CLAUDE_GOV_CTX_CRIT` (default 85%) — critical: ask the operator to generate
    a session handoff document (or, if it already exists, update it every turn) and
    steer toward a clean close. Emitted before `footer.sh` so the footer stays last.
- `scripts/context-meter.sh` — hybrid measurement, fail-open. Prefers the official
  `%` written by the opt-in statusLine snippet to `.governance/.context-pct`
  (authoritative, used while fresh per `CLAUDE_GOV_CTX_PCT_TTL`, default 60s);
  falls back to parsing the session transcript `usage` object. RTFM: Claude Code
  exposes context usage only to the statusLine, never to hooks — hence the bridge.
- Handoff documents are written by the model to `memory-system/handoff/HANDOFF-<session>.md`.
  They are versioned on purpose (committable) so a fresh session can resume; their
  presence is also the "approved/update-mode" marker for the guard. `hooks/project-state.sh`
  surfaces the latest one as `LATEST HANDOFF DOC` at SessionStart/PostCompact.
- Env knobs: `CLAUDE_GOV_CTX_WARN`, `CLAUDE_GOV_CTX_CRIT`, `CLAUDE_GOV_CTX_WINDOW`
  (override window size; needed on 1M sessions without the statusLine leg),
  `CLAUDE_GOV_CTX_PCT_TTL`. Statusline setup: `docs/statusline-optional.md`.
