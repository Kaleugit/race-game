## Architect Assessment
- Architect review completed: YES
- Decision summary: APPROVE the local change as a project-scoped stopgap. It is sound and minimal. It is additive, it sits right before the "ALWAYS re-assure telemetry" bullet it overrides, it points to a concrete source of truth (ADR-019), and it is fully reversible (run `install-hooks.sh` and supersede the ADR). The skill code and tests stay in the tree, so nothing inherited is deleted. Without this bullet, the next `update-upstream` run would silently re-wire telemetry. Step 7 says "ALWAYS ... regardless", and `install-hooks.sh` has no opt-out check, so ADR-019 would be undone on the first sync. The bullet is the correct place to stop that. Known weaknesses, accepted for now: (1) it is a project-specific edit (it names "race-game: ADR-019") inside a generic boilerplate file; (2) step 7's telemetry bullets change often upstream (DA-zero-toil, legacy-events migration), so a textual merge conflict on future syncs is likely; (3) the guard lives only in prose that the agent must follow; `install-hooks.sh` itself, and bootstrap Step 1b, still wire telemetry unconditionally, so a direct script run re-enables it. Options considered: (A) keep the local prose bullet only: cheap, but causes repeated conflicts and drift; (B) edit `install-hooks.sh` locally to honor a flag: also a protected path (`skills/*/scripts/*`), with a bigger local fork and the same conflict problem; (C) have the boilerplate adopt a generic, machine-checked opt-out: the root-cause fix. Chosen: A now, C upstream.
- Upstream action: ISSUE
- Rationale for upstream action: The root cause is in the boilerplate. It has no generic telemetry opt-out, and bootstrap Step 1b, `update-upstream` step 7 and `install-hooks.sh` all (re)install telemetry unconditionally. Every derived project that wants it off must fork protected files. A PR carrying this exact diff is not appropriate, because the bullet names a project and relies on prose-only ADR detection. The generic design should be decided by the boilerplate owners. Proposed design for the issue: a single machine-readable flag (for example `.governance/telemetry.disabled` or a `telemetry: disabled` key in a project config file) that is checked by `install-hooks.sh` (exit 0 with a clear "telemetry disabled by project opt-out" message, and optionally strip existing telemetry hooks), by `smoke.sh`/`migrate-legacy-events.sh`, by bootstrap Step 1b and by update-upstream step 7, all tied to a project ADR. Once upstream ships it, race-game replaces its local bullet with the flag, and the protected-file fork and its merge-conflict risk go away. NONE was rejected because it leaves the conflict and re-enable risk untracked. PR and PR_AND_ISSUE were rejected because the change is project-specific and the design is still open.
