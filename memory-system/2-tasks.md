# Active Tasks

## Bootstrap Gate (Advisory Before Normal Flow)
- Status: `PRE_BOOTSTRAP` | `INCOMPLETE` | `COMPLETE` | `READY_FOR_EXECUTION`
- Current Status: `COMPLETE`
- Rule: while status is not `READY_FOR_EXECUTION`, bootstrap/planning may continue with accepted risk and explicit human/architect awareness.
- Enforcement note: warning-only; there is no hard syntax CI block for incomplete bootstrap.
- Status meaning:
  - `PRE_BOOTSTRAP`: `BRIEFING.md` still in placeholder/template state.
  - `INCOMPLETE`: first real `BRIEFING.md` exists; formal docs are still evolving.
  - `COMPLETE`: bootstrap docs approved and ready for epic/task planning.
  - `READY_FOR_EXECUTION`: approved epics and normal task orchestration can start.
- Completion Criteria:
  - `INCOMPLETE`: `BRIEFING.md` has first project-specific content.
  - `COMPLETE`: `docs/PROJECT_SPECS.md` + `memory-system/1-project-context.md` are human-approved for epic decomposition.
  - `READY_FOR_EXECUTION`: `docs/EPICOS.md` approved by human and bootstrap gate updated by `gen-epics`.

## Task Board Rules
- Collaboration Mode: `Parallel` (default).
- WIP limit: `None`.
- Task source of truth: one file per task in `memory-system/tasks/`.
- Task index in this file is a consolidated artifact generated by `./scripts/reconcile-task-index.sh` (CI on `main`).
- Priority scale: `1` (highest) to `5` (lowest).
- Required fields per task file: `Status`, `Priority`, `Depends On`, `Blocked By`, `Branch`, `Workstreams`, `Execution Mode`, `Last Updated`.
- Task ID pattern: `TASK-<github-login>-<task-key>`.
- Task key patterns:
  - epic-linked task: `EP-<nnn>-<tt>`
  - ad-hoc task: `YYYYMMDDHHMMSS`
- Recommended task ID generation:
  - ad-hoc: `./scripts/generate-task-id.sh --login <github-login>`
  - epic-linked: `./scripts/generate-task-id.sh --login <github-login> --epic-id EP-001 --task-number 01`

## Status Legend
- `PENDING`
- `IN_PROGRESS`
- `BLOCKED`
- `COMPLETED`
- `CANCELED`

## Allowed State Transitions
- `PENDING -> IN_PROGRESS | CANCELED`
- `IN_PROGRESS -> BLOCKED | COMPLETED | CANCELED`
- `BLOCKED -> IN_PROGRESS | CANCELED`

## Task File Template
```markdown
# TASK-<github-login>-<task-key> - Brief task description

- Status: PENDING
- Priority: 1
- Description: Short task description
- Depends On: None (or TASK-<github-login>-<task-key>)
- Blocked By: None
- Branch: TASK-<github-login>-<task-key>-<role|workstream>
- Workstreams: [backend, testing] (or None)
- Execution Mode: Quick | Standard | Critical
- Last Updated: YYYY-MM-DD HH:MM

# Optional mode/state fields
- Planning: TASK-<github-login>-<task-key>-<role|workstream>-planning-[YYYY-MM-DD].md
- Report: TASK-<github-login>-<task-key>-<role|workstream>-report-[YYYY-MM-DD].md
- Evidence: PASS/FAIL + command/check output summary
```

Policy:
- Task branches must not manually edit the consolidated index in `2-tasks.md`.
- CI on `main` reconciles this index automatically.

## Mode Artifact Rules (Syntax Gate)
- `Quick`: objective `Evidence` (`PASS`/`FAIL` + command/check) is mandatory in `COMPLETED`.
- `Standard`: `Planning` is mandatory in `IN_PROGRESS/BLOCKED/COMPLETED`; `Report` is mandatory in `COMPLETED`.
- `Critical`: `Planning` is mandatory in `IN_PROGRESS/BLOCKED/COMPLETED`; `Report` is mandatory in `COMPLETED`.
